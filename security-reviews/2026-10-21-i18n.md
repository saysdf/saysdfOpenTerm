## Verdict

Verdict: OK to ship

No High finding. The catalog loader does what design D4 promises: language and domain names are
whitelisted (no path traversal through `language`, `SAYSDF_LANG` or directory names), every read
is capped (256 KiB per file, 64 files per language, 4096 entries, 4096 bytes per string), the TOML
parser has a recursion limit, non-UTF-8 and C0/C1 control characters are rejected, a broken file is
dropped as a whole and never stops the terminal. Catalogs are data: nothing in them can execute
code or bind an action. Placeholder substitution is a single pass (no re-expansion of argument
text), plural handling cannot panic, the global catalog is a poison-tolerant `RwLock` with no
self-deadlock, and the Windows FFI is sound.

One Medium (M1) and four Low findings remain. M1 (bidi/format characters pass validation) and L1
(`\t`/`&` in a translation are interpreted as menu-bar markup) are cheap and should go into the
next i18n step, before user catalogs are documented as something to download and share. L2–L4 are
hardening items for the migration steps that will touch the same code anyway.

## 1. Threat model checks

### 1.1 User catalogs: paths, sizes, symlinks, encoding

- **Language names.** The language reaches the file system only through `catalog::load`
  (`catalog.rs:241`), guarded by `valid_lang` (`catalog.rs:136-142`: `[a-z]{2,3}(-[A-Za-z0-9]{2,8})*`),
  and `user_languages` (`catalog.rs:161-176`) only accepts `read_dir` entries passing the same
  check. Before that, `resolve` (`lib.rs:69-101`) only produces tags from `detect::normalize`
  (`detect.rs:5-33`, ASCII whitelist, cuts at `.`/`@`, rejects `C`/`POSIX`) or members of
  `languages()`. `../x`, `ru/..`, `C:\x`, `\\srv\share`, `con.` cannot survive either filter. The
  test `names` (`catalog.rs:304-313`) covers the traversal cases. OK.
- **Domain names** come from `read_dir` entries filtered by `valid_domain` (`catalog.rs:145-151`,
  `[a-z0-9_-]{1,64}`); not user input. OK.
- **Sizes.** `read_user_file` (`catalog.rs:201-218`) checks `metadata().len()` and then the actual
  byte count after `fs::read` (covers a TOCTOU grow); `user_files` truncates to 64 sorted files
  (`catalog.rs:191-197`); `parse` enforces 4096 top-level entries and 4096 bytes per key/value
  (`catalog.rs:73-75`, `57-66`). Nested tables (`_accel`, plural forms) have no own entry cap but
  are bounded by the 256 KiB file. OK.
- **Symlinks / special files.** `is_file()` and `metadata()` follow symlinks, so a symlink to a
  large file is capped like any file; a symlink to a FIFO or device is not `is_file()` and is
  skipped, so `fs::read` cannot block on `/dev/zero` or a pipe. OK.
- **Encoding / TOML depth.** `String::from_utf8` rejects non-UTF-8 (`catalog.rs:216`). The
  workspace `toml = "0.8"` resolves to `toml 0.8.23` / `toml_edit 0.22.27`, whose parser has a
  recursion limit of 80 (`toml_edit-0.22.27/src/parser/mod.rs:97`), so `a = {b = {c = ...}}`
  nesting errors cleanly instead of overflowing the stack. Any error rejects the whole file with a
  warning (`catalog.rs:244-249`). OK.
- **Windows reserved device names** (`con`, `prn`, `aux`, `nul`) pass `valid_lang` and
  `valid_domain`. For a language dir `read_dir("<dir>\con")` simply fails (nothing loaded). A
  catalog file `con.toml`/`nul.toml` can only exist if created through a `\\?\` path by someone
  who already writes to the config dir (equivalent to editing the Lua config), and `is_file()` on
  the device handle fails, so it is skipped. Out of the threat model; cheap to harden (I1).

### 1.2 Can a catalog execute code or drive the terminal?

- The file is parsed by the `toml` crate into a `toml::Table` and reduced to `String`s and
  `HashMap<String, String>`; nothing is evaluated. The Lua side receives only strings from the
  native module (`lua-bundle/src/i18n.rs:89-111`). OK.
- Terminal escape sequences: `check_text` (`catalog.rs:57-66`) rejects every `char::is_control()`
  (Unicode Cc: C0, DEL, C1 including U+009B CSI) except `\n` and `\t`, in keys and in every
  translation/plural form (`catalog.rs:98-104`). This matters because `window:set_right_status`
  (used by `saysdf.status` for `util.notify` messages, `util.lua:349`) interprets escape sequences
  inside `Text` items; with ESC and C1 blocked a catalog cannot inject SGR/OSC through that path.
  OK.
- Bidi overrides and invisible format characters are **not** rejected — see M1.
- `\t` is allowed and is menu-bar markup — see L1.

### 1.3 Placeholders and plurals

- `placeholders()` (`format.rs:5-36`) restricts names to `[A-Za-z0-9_]+`, rejects unbalanced
  braces, and `parse` requires a translation's placeholder set to be a subset of the key's
  (`catalog.rs:97-104`, plus `n` in plural forms). A translation therefore cannot reference an
  argument the code does not pass. At format time an unknown placeholder is copied literally
  (`format.rs:62-64`), never an error or a panic.
- `format()` (`format.rs:40-72`) is a single left-to-right pass: argument values are pushed
  verbatim and never re-scanned, so `{...}` inside selected text or a path is not expanded. No
  format-string behaviour. Slicing is on ASCII `{`/`}` positions, so no char-boundary panics.
- Expansion is bounded by `MAX_TEXT_BYTES` x `argument length`, but a placeholder may repeat
  ~1 300 times in one translation — see L2.
- Plurals: Lua `tn` converts `f64` with `is_finite()` guard and a saturating `as u64`
  (`i18n.rs:102`), so NaN, infinities, negative and huge values give 0 or `u64::MAX` without
  panic; `plural_category` (`format.rs:76-119`) uses `%` on `u64` and a default arm; a missing
  form falls back to `other`, then to the English string (`lib.rs:200-219`). `Catalog::text` on a
  plural entry uses `other` or the key (`lib.rs:190-194`). No panics.

### 1.4 Accelerator overrides (`[_accel]`)

- Parsing accepts any id (unvalidated string) and a value of 1–16 non-control chars
  (`catalog.rs:83-94`); the maps of all domain files of a language are merged into one
  (`catalog.rs:53`). An override can only name an **existing** registry entry id and a key; it
  cannot add an entry, change an action, or attach a key binding — bindings stay in Lua/Rust.
- **Not consumed yet.** `i18n.accel()` (`i18n.lua:61-63`) has no callers; `palette.add` still
  takes `accel` from the code (`palette.lua:59-77`). So today `_accel` has no effect. The risks
  below (L4) apply to the migration step that wires it into `palette.add`.
- Uniqueness: `palette.add` rejects a second entry with the same `(menu, accel)` slot (first
  wins, `palette.lua:69-76`, with a `util.notify`), and `saysdf_set_bar` re-checks per menu
  (`saysdf_menu.rs:74-95`) but turns a duplicate into an **error of the whole call**
  (`saysdf_bars.rs:342`), which `menu.lua:141` invokes outside `pcall`.

### 1.5 Global state and concurrency

- `CURRENT: RwLock<Option<Arc<Catalog>>>` (`lib.rs:110`); every lock uses
  `unwrap_or_else(|e| e.into_inner())`, so a panic elsewhere cannot poison it into a crash.
- `current()` (`lib.rs:155-165`): the read guard in the `if let` scrutinee is dropped at the end
  of that statement, before `init_from_env()` takes the write lock — no self-deadlock. Two threads
  racing on first use both load and the last `set_current` wins; readers always see a complete
  `Arc<Catalog>`. OK.
- Lua: the per-state catalog is mlua app data; `catalog()` (`i18n.rs:18-26`) drops the
  `app_data_ref` before `set_app_data`, so no `RefCell` double borrow; `LuaCatalog(Arc<Catalog>)`
  is `Send + Sync`, as the `send` feature of mlua requires. Each config evaluation gets its own
  catalog and `init` also replaces the process one (design D6), so the last loaded config wins —
  accepted in design "Risks".
- Tests: `lib.rs:300` and the lua-bundle tests mutate the process catalog; `cargo test` runs them
  in threads of one process, so cross-test interference is possible (not a security issue; noted
  for flakiness).

### 1.6 `SAYSDF_LANG` into child processes

- `init.lua:62-66` sets `config.set_environment_variables.SAYSDF_LANG` to the value returned by
  `resolve`, i.e. English, an embedded language or a user dir name that passed `valid_lang`; a
  user-set value is left alone. The child (`init_from_env`, `lib.rs:149-152`) re-normalizes and
  re-validates it, and only looks under `$SAYSDFTERM_CONFIG_DIR`/`~/.config/saysdfTerm/locales`
  with the same caps. Terminal output cannot change the environment of the terminal or of new
  panes, so there is no path from untrusted output to this variable. OK.
- `home_dir()` (`identity/src/lib.rs:86-96`) and `user_config_dir()` read only env vars; a
  process that controls those already controls the tool's environment. OK.

### 1.7 Windows language detection (FFI)

`detect.rs:61-75`: `GetUserDefaultUILanguage` returns a `LANGID`; `LCIDToLocaleName(lcid, buf,
85, 0)` receives the real buffer length (`LOCALE_NAME_MAX_LENGTH`), the return value `n` includes
the terminator, `n <= 1` is treated as failure, and the slice `..n-1` is at most 84 within an
85-element buffer; `from_utf16_lossy` cannot panic; the result is re-normalized through the ASCII
whitelist. The `windows-sys` features `Win32_Foundation`/`Win32_Globalization` are declared. Sound.
Nit (I4): `GetUserDefaultLocaleName` would avoid the LCID round-trip and handle custom locales
without an LCID (today they yield `None` -> English, which is acceptable).

### 1.8 Rules 3 and 5 elsewhere in the diff

- No network, no process spawning, no writes anywhere, no secrets. `build.rs` only embeds
  `saysdf/locales/**/*.toml` with `include_str!`; a malformed embedded file is a warning at
  runtime (`catalog.rs:236-239`) and a failing test (`lib.rs:344-352`), not a panic.
- Rule 5: catalogs are read in `saysdf.setup` (once per config load) and the Lua fallback path
  `catalog()` loads with `user_dir = None` (no disk I/O). The Rust fallback `current()` ->
  `init_from_env()` *does* scan the config dir — see L3.
- `languages()` (`lib.rs:56-63`) walks every language dir and lists its files on each `init`,
  even when `language` is explicit. Bounded and per config load; fine.

## 3. What was checked and found correct (summary)

- Path handling: `valid_lang`, `valid_domain`, `detect::normalize`, `resolve` prefix fallback
  (`&cand[..i]` on ASCII only), `user_files` discovery; `SAYSDF_LANG` end to end.
- Limits: file size (pre- and post-read), file count, entry count, text length, control chars,
  UTF-8, TOML recursion; whole-file rejection with one aggregated `log_warn` (`i18n.lua:44-47`).
- `format()`: no re-expansion, no panics, `{{`/`}}` escapes, literal copy of malformed input.
- Plural rules and the Lua `f64 -> u64` conversion.
- `RwLock` poison handling, guard lifetimes, mlua app-data borrow discipline, `Send` bounds.
- Windows FFI buffer handling and the `cfg` split (Windows / everything else via POSIX vars).
- `build.rs`: only `include_str!` of `.toml` files under `saysdf/locales`, sorted, with
  `rerun-if-changed`.
- No new network, process, write or secret-handling code; new dependency surface is zero
  (`toml`, `windows-sys`, `tempfile`, `regex` were already in `Cargo.lock`).

## 4. Not checked / limitations

- Nothing was compiled or executed; the unit tests were read, not run.
- The GUI rendering of bidi text in `Element::Text` (whether WezTerm's shaper honours RLO in bar
  elements) was not traced; M1 is rated on the unprotected sinks regardless.
- The macOS branch is the POSIX-variable path; no CoreFoundation code exists yet (design open
  question).
- `saysdf/i18n/tests/sources.rs` was skimmed only to confirm it is a test-time source scanner.

## 5. Recommendations (order)

1. M1 + L1 together in the next i18n step: extend `check_text` with the invisible/format set and
   `\t`, sharing the character set with `saysdf_bars::is_invisible_format`; add tests.
2. L2: cap placeholder repetitions in `parse` (and optionally a hard output cap in `format`).
3. L3: decide the lazy-init policy before any GUI-process Rust code calls `Domain::t`.
4. L4: apply when wiring `_accel` into `palette.add` (validate with `saysdf_keys::parse`, apply
   only to free slots, `pcall` around `saysdf_set_bar` in `menu.lua`).
5. I1, I5 as tech-debt entries at the orchestrator's discretion.
